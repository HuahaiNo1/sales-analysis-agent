# 销售分析助手最终交付规格

文档日期：2026 年 10 月 7 日  
适用项目：sales-analysis-agent  
文档用途：统一最终目标、功能边界、技术合同和验收出口，作为后续 Codex 开发与验收的单一蓝图

## 一 结论与交付目标

最终交付是一个面向销售运营与业务分析人员、单组织少量用户使用、能够在用户本地运行的销售分析应用。用户可以查询 Contoso 销售数据，比较期间与业务维度，进行有明确上限的贡献拆解和重点下钻，将有证据的复盘保存为独立报告，并在以后重新打开、补充人工备注和导出。

完成的标准是业务闭环可用、数据口径可信、权限正确、失败可恢复，以及用户亲自完成本地服务验收。增加更多模型、数据源、配置界面或部署设施，不构成本轮完成条件。

本规格是目标与验收要求，不是已完成声明。现有查询底座已经建立，报告持久化与有限自主复盘属于本轮增量开发。2026 年 10 月 7 日用户另行授权继续自主开发十小时；该执行窗口不改变本规格的范围、不代表到点自动验收，也不授权公网部署或额外付费。

## 三 用户与业务闭环

### 3.1 用户职责

- 销售运营：看总体销售、门店/类别变化，定位需要业务复核的重点，保存复盘并补充业务说明
- 业务分析人员：核对指标、筛选与期间，沿证据做有限下钻，检查贡献是否对账，导出可解释结果
- 当前演示账号：用于验证全范围与受限门店范围差异；账号名称中的 admin 不等于已建成生产级管理员体系

### 3.2 完整使用路径

1. 登录后确认账号、数据集、数据覆盖范围、模拟属性和当前可见门店
2. 通过看板或对话发起日常问题；问题缺少必要期间、指标或比较基准时，系统只问缺失项
3. 获得包含真实期间、指标口径、总量、图表、聚合明细和证据提示的结果
4. 选择固定销售复盘入口，明确本期与对比期及筛选；系统在有上限的范围内补齐分析
5. 阅读总体变化、维度贡献、有限下钻、规则提示、数据局限和待验证解释
6. 明确点击保存报告；系统将必要事实、证据和图表数据一次性持久化
7. 在报告列表重新打开，修改标题、人工备注或建议；导出 Markdown 或自包含 HTML
8. 如需更新期间、口径或数据，重新计算并另存新报告；不覆写旧报告事实
9. 删除进入可恢复状态；重启后未删除的报告仍可用。权限变化时仍服从当前授权

报告输出给用户本人。系统不自动发送报告给他人、不定时生成报告、不替用户执行促销或业务动作。

## 五 数据与指标语义

### 5.1 数据边界

数据为 SQLBI Contoso V2 官方生成器产生的模拟零售数据：97,215 张订单、232,928 条订单行，销售日期从 2023-01-01 到 2025-12-31；金额统一 USD，汇率为 1。销售事实只使用 fact_sales，维度为商品、门店、客户地理与日期。日期维表含 2026 年，不代表 2026 年存在销售事实。

数据版本基线为 contoso-v2-2023-2025-692e0347d360。年度增长与季节性来自模拟生成配置，不能描述为某真实企业或市场的经营结论。在线门店是源数据的一种门店，不推断为可靠交易渠道；门店国家和客户国家不可混为一谈。

### 5.2 指标合同

| 指标键 | 中文口径 | 计算与限制 |
| --- | --- | --- |
| sales_amount | 折扣后销售额 | SUM(quantity × net_price)；net_price 已经是折后单位售价，不再重复减折扣，也不是实收款 |
| order_count | 去重订单数 | COUNT(DISTINCT order_key)；按商品/类别分组可能重复覆盖订单，不允许把分组计数相加当总订单 |
| units_sold | 销售数量 | SUM(quantity)；单位为件，不能换称重量或客户数 |
| avg_order_value | 平均订单金额 | 总销售额 ÷ 同范围去重订单数；无订单为 null；不支持商品/类别筛选或分组 |
| gross_profit | 商品毛利 | SUM(quantity × (net_price − unit_cost))；未扣税费、物流、营销等经营费用，不是净利润 |

金额与中间运算使用 PostgreSQL NUMERIC / Python Decimal；API 的金额和数值结果沿用十进制字符串，前端只格式化，不能自行补算 KPI、贡献或百分比。最终显示才四舍五入。AOV 不做分组均值的平均，也不与订单数一起做加总贡献瀑布图。

### 5.3 时间与比较

期间统一为按订单日期的左闭右开区间。2025 年 9 月表示 [2025-09-01, 2025-10-01)。每个期间保留 1–366 天限制，并须在实际销售覆盖内。同比、环比必须解析成具体日期并展示；无法确定锚点时先澄清，不把当前系统日期直接套入历史数据。

差额为本期减对比期。沿用既有变化率语义：差额 ÷ 对比期绝对值 × 100；负基数时明确标注“以对比期绝对值为分母”，避免误导。对比期为 0 或缺失时，变化率为不适用，不能显示无穷大或虚构 100%。两个期间天数不同或存在重叠时明确提示；不擅自年化、日均化或声称公平可比。

时间趋势按真实日期显示。本轮不额外承诺复杂跨期日历对齐；不能把不同月份的自然日期简单合并后填零，制造不存在的同比走势。比较结论以经过独立汇总的本期/对比期值为准。

### 5.4 贡献与边界情况

贡献拆解只适用于销售额、销量和商品毛利。对一个互斥且完备的分组，所有组差额之和必须等于总差额。Top N 只截断展示，不能改变总量；隐藏部分以“其他分组合计”补齐瀑布图和对账。不同维度的贡献图各自解释同一总差额，不能把类别贡献和门店贡献再相加。

- 两期均无事实行：明确“无数据”，不生成有经营含义的结论；可保存带空数据声明的事实快照
- 有事实行但结果为 0：属于零值，不等同于无数据
- 某组只在本期出现：标为“对比期无记录/本期出现”，不据此断言新产品上市
- 某组只在对比期出现：标为“本期无记录”，不据此断言停售或业务流失
- 总变化为 0：仍可展示正负抵消的金额贡献；净贡献占比为不适用
- 负值与负向变化：保留符号，不取绝对值冒充增长；绝对值仅用于变化幅度排序
- 缺成本或其他必需基础：不得把缺失当 0；给出不可计算原因，不补造净利润
- 商品/类别范围内不适用的 AOV：不显示旧的全局 AOV，也不静默换成部分订单平均值
- 超出日期、行数或查询范围：给出具体可修正的限制，不偷偷截断后称完整结果

## 六 有界自主复盘

### 6.1 固定模板与分析路径

本轮只建立一个销售复盘主模板 sales_review_v1。门店专题是同一模板在授权门店内加筛选的表现形式，不另建模板平台。指标定义、模板结构和规则放在代码内的小型注册表中，无面向用户的配置后台。

复盘必须同时具备明确本期、对比期和范围。默认围绕销售额展开；可加总的其他主指标仅复用同一已验证路径，不因切换指标新增无限分析方法。分析按以下有限步骤执行：

1. 校验当前身份、期间、指标与筛选，冻结本次分析输入
2. 获取所选单一可加总指标的总体比较、本期/对比期值和差额
3. 分别做类别和门店贡献，标明正向、负向和主要变化项
4. 用户开启下钻时，根据确定性贡献排序选一个重点，最多做一次类别 → 商品下钻；没有有效重点则跳过
5. 对规则进行确定性计算，由唯一 analysis 子 Agent 整理已有证据，不让模型猜测数字或另取数据
6. 生成结构化复盘结果，明确已分析范围、未做事项、证据局限与下一步可人工验证的问题

它的自主性体现在按证据选择重点并完成有限流程，不在于自由探索数据库或无限尝试。一次复盘最多 4 个 QuerySpec：总体比较、类别贡献、门店贡献，以及可选的一次商品下钻；“一次 QuerySpec”不等于一条物理 SQL。五指标和时间趋势继续由既有看板/日常查询提供，本轮不要求复盘额外执行五指标与趋势全套查询。复用已完成证据，禁止为了凑章节重复查询。普通聊天继续保持原有单次受控查询路径，不整体放开为多轮无限探索。

### 6.2 规则提示

“异常”仅指命中明确、可展示的业务分析规则，不宣称统计异常或因果关系。每条提示包含 rule_id、实际值、适用条件、阈值或排序依据、证据引用和局限。

最小规则覆盖：两期销售变化达到明确幅度阈值；绝对贡献变化最大的若干分组；仅在单期出现的分组；零基数或数据不足导致不可比较。变化阈值例如 20%、重点取前 3 项可作为首版工程默认，必须在界面和报告中展示并保留参数，不能把默认值包装为用户确认的经营红线。修改默认参数属于可审查的小改动，不引入配置 UI。

语言示例：“类别 A 的销售额变化为 X，是本次类别分组中绝对变化最大的项”是证据事实；“可能需要检查商品组合变化”是待验证建议；“促销导致销售下滑”缺少因果证据，不得输出。规则未命中不等于经营健康，数据缺失也不等于没有问题。

### 6.3 执行限制与失败

继续使用固定主 Agent 和且仅一个 analysis 子 Agent。主 Agent 选择受控工具并提交结构化请求，分析子 Agent 只处理本次获授权证据句柄。有限复盘由后端确定性服务执行计划，模型没有直接 SQL、数据库凭据、shell 或通用文件工具。

沿用既有每次运行最多 12 次模型调用、单次供应商请求 30 秒、SDK 自动重试为 0、SQL 语句超时 10 秒等已实现边界。复盘补充总流程超时和证据体积上限：冻结快照最多 1 MiB，最多 4 份证据，每份最多 101 行展示聚合（含“其他”）。总流程 180 秒、导出 10 MiB可作为可调整工程默认；实际实现若采用更严格合理值，在 API 与界面一致披露即可。这些是防止失控的技术默认，不是承诺的性能 SLA。

用户取消、权限变化、预算不足或工具错误时停止后续动作。不得继续隐藏调用，不自动换付费模型。发生错误或取消的本次复盘不发布部分结果；其他此前已完成的独立查询不受影响。无数据、无变化、下钻关闭、类别歧义或无候选等正常提前结束必须写明停止原因，不能伪装成执行了所有步骤。错误信息区分用户需要补充的条件和系统失败，不能把内部参数错误变成要求用户反复确认的问题。

## 七 报告生命周期与持久化

### 7.1 保存的含义

保存报告是在服务端一次事务中复制足够的事实和证据，创建独立实体。报告不是指向 result_id 的收藏夹，也不是只存一段模型文字。源聊天结果过期、旧会话不再活跃、应用重启或模型不可用时，仍能重新打开和导出已保存报告。

报告最小内容包括：标题、本期与对比期、筛选和范围、数据/指标/模板版本、生成时间、指标口径、聚合值、图表数据、证据索引、规则参数、确定性观察、分析文字及其性质、数据局限。source_run_id / source_result_id 可保留作追溯信息，但报告不能依赖其生命周期。

事实部分固定不变。模型的生成解读也作为当时结果保留并标明来源，用户的后续备注与建议与之分开。保存以后不因数据刷新或模型变化静默重算。原有聊天 result 的哈希可沿用作来源信息，不再建设第二套哈希链或不可用的“强审计”系统。

### 7.2 简单状态与操作

| 状态 | 用户可见含义 | 行为 |
| --- | --- | --- |
| generating | 正在形成复盘或保存 | 复用现有 run 的进度与取消，不另做后台任务平台 |
| ready | 快照已完整保存 | 可查看、编辑允许字段、导出、删除 |
| failed | 未得到可用快照 | 展示原因；明确重试才新发起，不给出伪成功报告 |
| deleted | 已放入回收站 | 普通列表隐藏，可恢复；事实数据不因软删除立刻物理清除 |

存储实现可只给报告表设置 ready/deleted，将 generating/failed 放在现有 run 中；不要为了文档状态拆出额外工作流引擎。

最小删除流程采用软删除和恢复。用户同意“报告保留到主动删除”为产品保留策略，不等于授权助手现在删除任何报告，也不等于授权永久清空。永久删除和自动清理不作为本轮必需功能。删除后不再出现在普通列表或普通导出路径，恢复后仍须通过当前权限检查。

### 7.3 编辑与并发

仅标题、人工备注和建议可修改，不允许编辑 KPI、期间、QuerySpec、证据聚合或规则计算结果。采用一个 revision 整数或等效版本令牌即可：客户端提交 expected_revision，过时返回 409 并提示刷新；不能无声覆盖另一窗口的编辑。无须历史版本树、逐字合并、多人实时协作。

保存动作使用与用户/源运行绑定的幂等键，重复点击产生同一个报告，不重复计费或创建多份。重新计算使用新运行与新报告 ID，旧报告保持不变；可以带一个来源报告 ID 帮助理解，不需要分支版本图。

### 7.4 当前授权永远优先

每次列表、读取、编辑、导出、删除、恢复均验证 owner 和当前身份。报告保存生成时的覆盖范围，读取时要求该快照覆盖的数据仍全部在当前授权内。权限扩大不自动扩展旧快照；权限缩小到不能覆盖快照时，整份报告拒绝展示和导出，提示按当前范围重新生成。不要临时删除部分行后继续展示旧总额。

列表和错误页也不能泄露被撤权报告中的数字、敏感标题或证据摘要。猜到 report_id 不授予访问权。服务端是授权依据；前端隐藏按钮不是安全控制。重新登录另一账号时，清除前端缓存中的前一账号内容。

## 八 技术框架与模块职责

采用模块化单体，保留 Python / FastAPI、PostgreSQL、Vue 3 / TypeScript、DeepAgents 与现有 DeepSeek 官方 API 接入。无需拆微服务、消息总线、向量库或独立报表服务器。先复用已安装且成熟的组件，只有既有组件确实缺能力时才增加依赖。

### 8.1 依赖方向

HTTP 路由 → 应用服务 → 领域合同与确定性计算 → 数据访问。Agent 编排通过受控服务接口取得句柄；前端通过 API 取得结构化结果。共享类型和错误码放在底层合同，业务模块不得反向导入路由。

| 模块 | 拥有的职责 | 不应承担 |
| --- | --- | --- |
| identity / scope | 登录身份、当前门店范围、对象归属判断 | 生成分析结论或信任模型传来的身份 |
| catalog / schemas | 五指标、维度、QuerySpec、模板与规则合同 | 任意运行时 SQL 表达式配置 |
| query | 固定 SQL 编译、参数绑定、Decimal 聚合和贡献对账 | 文本报告排版或前端状态 |
| agent | 主/唯一子 Agent、工具分发与模型边界 | 直接 SQL、人工算数字、绕过预算 |
| review service | 有界计划、证据合并、规则计算、重点下钻 | 无界自主探索或文件工具 |
| report service / repository | 快照创建、授权、轻量编辑、列表与软删除 | 调用路由函数、读取过期聊天结果作为唯一证据 |
| export | 从已授权快照确定性生成 Markdown / HTML | 新查数据、再调用模型、加载外部脚本 |
| budget | 所有主/子调用共享预留、结算与失败保守占用 | 每个模块另开一份账本 |
| Vue 页面与 API 客户端 | 状态展示、交互、格式化与请求取消 | 计算业务指标或自行判定权限 |

避免为“模块化”给每个函数建抽象工厂。把当前 main.py 中新增业务提取到清楚的小模块，复用已有身份、查询、预算逻辑即可；不得跨路由调用业务，也不为一次增量重写全部历史代码。

### 8.2 最小数据模型

| 实体 | 保留或新增 | 核心内容 |
| --- | --- | --- |
| fact_sales 与维表 | 保留 | 现有 Contoso 粒度和只读分析边界 |
| sessions / conversations / runs | 保留并小幅扩展 | 身份、状态版本、请求幂等、运行类型、进度、失败、review 结果引用 |
| results | 保留 | 现有 24 小时冻结交互结果和 CSV |
| reports | 新增 | id、subject、source_run_id、title、comment、suggestions、revision、facts、created_at、updated_at、deleted_at |
| 费用账本 | 保留 | 同次开发共享累计金额与未决预留；不另建报告专用账本 |

ReportFacts 的固定顶层合同为 schema_version=report_v1、kind=query/review、generated_at、dataset_version、metric_version、scope、result、review。scope 包含 allowed_store_ids、scope_label、scope_version。result 保留完整 QueryResult；review 为空或包含模板、请求、证据、findings、flags、assumptions、suggestions、rule_config、query_count、max_queries 与 stop_reason。证据记录包含 evidence_id、role、title 和完整 result；其中保存 QuerySpec、字段/单位、展示聚合行、总量、比较总量、差额、完整性/截断标记和图表数据。所有 evidence_ids 必须能在同一快照内解析。

这些字段可用一个 JSONB 快照配合少量索引列完成。仅为实际列表查询建立必要索引。无需复制全部销售明细、无限原始行或日志，也不为每段报告拆多张关系表。报告查询路径不得顺着外键要求源 results 仍存在。

### 8.3 API 合同方向

保留现有 /api/auth、/me、/catalog、/dashboard、/conversations、/runs、/results 及结果 CSV。复盘优先复用 POST /api/conversations/{id}/runs，以可选 review={period, comparison, metric, filters, drill_down} 表达期间、对比期、单一可加总主指标、筛选及是否做有限下钻；filters 默认为空，drill_down 默认为 false；message、client_request_id、expected_state_version 的幂等和并发语义不变。GET run 返回 query/review 类型和结构化复盘内容，不能只靠模型文本判断完成。

新增报告接口如下，以下是已对齐的首版实现合同，随后同步 docs/api.md；不因同义命名增加额外业务要求：

| 接口 | 核心合同 |
| --- | --- |
| POST /api/reports | 输入 run_id、title、可选 comment/suggestions、client_request_id；仅从 succeeded/no_data 且源证据当前有效的运行保存；重复同键同内容返回原报告，异内容 409 |
| GET /api/reports | deleted=false 为普通列表，true 为回收站；limit/offset 分页；只返回当前可访问报告，不泄露不可见标题和统计 |
| GET /api/reports/{id} | 重新授权，返回 facts 与可编辑字段、revision；已删除报告可在回收站检查并恢复 |
| PATCH /api/reports/{id} | 只接受允许编辑字段和 expected_revision；事实字段一律拒绝 |
| DELETE /api/reports/{id} | 传 expected_revision，软删除；重复当前状态为无变更，但版本仍须匹配 |
| POST /api/reports/{id}/restore | 传 expected_revision，恢复软删除报告，仍检查权限 |
| GET /api/reports/{id}/export | format 为 markdown 或 html，默认 markdown；当前授权后确定性导出；已删除须先恢复 |

标题去空白后 1–120 字符，comment/suggestions 各最多 4,000 字符；revision 从 1 开始，仅有效编辑、删除和恢复递增。报告不因数据版本更新而失效，嵌入的旧 expires_at 仅是来源历史字段，不能当报告过期时间。

现有 QuerySpec 最多 2 指标、2 分组、8 个筛选，单筛选最多 20 值，展示最多 100 行，完整分组最多 20,000 行。review 的 filters 最多 7 项，给受控下钻留一个筛选位。整体请求上限沿用既有合同。

沿用未登录 401、对象不可访问 404、版本冲突 409 与输入校验错误语义。超时、预算不足、范围变化、快照超限等使用稳定错误码和可读说明。不要把技术失败统一变成 needs_clarification。

### 8.4 导出安全

Markdown 和 HTML 都来自已持久化快照，不依赖浏览器当前临时图表。导出包含期间、范围、数据版本、模拟声明、指标口径、证据表和规则说明。HTML 自包含、可离线阅读，文本严格转义，无外部脚本、外部请求或模型生成的可执行 HTML。图表优先用经过验证的静态结构；没有安全图形路径时提供完整可读数据表即可，不能因此阻塞所有导出。

已有 CSV 继续防公式注入，只导出授权聚合行，不新增客户明细下载。文件名受控，导出体积受限，超限明确报错，禁止悄悄丢弃关键证据。已下载到用户本地的文件无法由系统追溯撤回；“当前授权校验”指每次应用内访问与新导出。

## 九 前端体验与并发约束

保留看板和对话，增加清楚的“销售复盘”与“报告”入口即可，不重做整个视觉系统。复盘表单显示具体期间、对比期、权限内筛选和当前规则；表单与自然语言入口最终调用同一受控合同。

运行时展示可信进度阶段而非虚假的百分比。取消后直到工作实际停止才显示 cancelled。错误后保留输入供修正，但不能把上一个成功结果冒充当前结果。快速新建会话、连续发送、切换报告、退出登录和重新登录均须有请求归属检查；迟到响应不得覆盖新会话或新账号页面。

图表按钮与“换成表格”等纯展示追问继续复用同一获授权冻结结果，不能重查 SQL 或消耗模型额度。报告打开、标题编辑、备注编辑、导出与恢复也不调用模型。事实部分只读，人工输入有明确标签。移动端保持主要入口、数据表和操作可用，不扩展为独立移动应用。

## 十 费用与运行边界

常规开发、回归和稳定性观察使用 mock，仍运行真实 Agent 图、受控查询和数据库。mock 是有限演示问法转换器，不宣称与真实语言模型具有相同理解能力。真实模型使用现有 DeepSeek 官方 API / deepseek-flash 配置，不擅自升级型号或引入备用供应商。

原用户总额度为人民币 5 元，现有应用保守门禁为 4.8 元。最近已知跨环境占用 2.252764 元，其中未知预留 2.113536 元；这些是估值与风险占用，不是供应商账单。用户最新一轮 E2E 如有真实调用，其新增费用尚未在本规格中核实；当前云端旧账本不代表最新全局余额。

在任何新真实调用前，核对本地新增消费与原账本累计状态，保留未知预留，确认同次额度仍可覆盖。不能删除账本、换目录、换环境或创建空账本来恢复额度。沿用全主/子调用共享原子预留与严格 usage 结算；未知失败不能擅自释放风险占用。实际价格与供应商限制须在启用真实调用前重新核实。

本轮只需少量关键真实流程验证，全部限于原预算；若账本未核对、剩余额度不足或凭据尚未由用户手动配置，则保留 mock 验证成果并明确 live 待验，不增加预算。长时稳定性测试不使用付费模型。不会因“继续开发十小时”推定追加费用授权。

### 12.2 小规模稳定性与真实调用

在同一最终候选版本上，做一次约 30 分钟的少量用户 mock 混合操作观察，可使用 2–3 个并发会话作为工程测试负载：查询、复盘、保存、列表、重开、导出、取消与切换。记录错误、运行状态、资源变化和数据一致性，不虚构生产并发量或可用性 SLA。

停止条件是观察窗口结束且未发现阻断问题；发现问题时修复对应问题并定向复验。仅在修复会影响稳定性结论时重新做受影响的观察，不无限循环全套长测。重启持久化、范围隔离和失败恢复仍要单独验证，不能由“运行了三十分钟”自动推断通过。

随后在预算核对后，以少量 live 验证主 Agent / analysis、复盘证据与关键真实语言路径。精确记录调用数、估值和未决预留；mock 通过不替代 live，live 通过也不替代浏览器或用户本地验收。

### 12.3 用户手动本地验收

最后由用户在自己的本地服务上完成：启动登录 → 一条查询与比较 → 一次完整复盘 → 保存报告 → 重启后重新打开 → 编辑备注 → 导出 → 删除与恢复 → 核对范围隔离。用户可检查实际工作体验和说明是否足够，无须亲自复跑开发者全部测试。

自动测试全绿只代表自动覆盖通过；“用户已验收”须有用户实际反馈。部署方案讨论放在这个环节之后；本轮不能以还没选 Docker、Linux、公网域名或长期主机为由阻止用户验收。

### 12.4 完成声明

只有同时满足以下条件，才可称“本轮最终交付完成”：P0 功能闭环全部可用；五指标、贡献和事实证据正确；报告跨 TTL/重启保留；当前权限不泄露；关键失败可恢复；小规模稳定性与可执行的 live 验证范围如实记录；用户手动本地验收接受；文档与交付版本一致。

如 live 因原预算或凭据受阻，必须列为明确待验项，请用户决定是否接受这一边界，不能代替用户默认通过。若仍有 P0 阻断项，继续在授权范围内修复，或清楚说明需要的输入；不通过另开功能阶段掩盖缺项。

## 十三 文档收口与范围变更

仓库只保留一份权威最终规格，建议为 docs/final-delivery-spec.md；本次附件是其内容蓝图，落入仓库属于后续实施。README 负责启动和使用，docs/api.md 负责接口，STATUS 负责当前完成/待验状态与最新证据。现有必要来源文档继续保留，但不为每次微小改动新建一份几乎重复的规划报告。

修复指恢复已承诺行为，例如越权、错误数字、串会话、持久化丢失或已支持流程失败。新增需求指扩展数据、角色、模板、部署、调度、预测或新业务动作。新增“必须”应说明替换哪个现有项，或明确推迟到本轮交付后；不能不改完成条件却持续扩大实现范围。

本轮真正待定的只有：最新累计预算与少量 live 可执行性；最终本地候选版本的人工验收结果；验收之后是否需要部署及采用何种方式。数据源、报告保留、用户群和功能大边界已经确认，不再重复发问。

本规格可直接交给 Codex 分阶段执行。它规定产品结果与验收合同；代码修改、外部发布、付费或删除数据等具体行动，仍以用户实际授权为准，不能仅因出现在规格中就推定获得操作许可。
