## 已通过：真实 API 用户流

- 完整复盘执行 4 个 QuerySpec，生成整体、类别、门店和一次商品下钻的 4 份证据；唯一 analysis 子 Agent；证据引用可解析，贡献行与相应变化总额以 Decimal 对账
- 停止分支：关闭下钻 3 次查询、已按类别筛选 3 次查询、无数据 1 次查询。不是递归规划，也不是把 4 个 QuerySpec 当作仅 4 条 SQL
- 同一运行请求、同一保存请求幂等；相同请求 ID 携带不同内容拒绝
- 报告冻结指标定义、事实和证据；批注编辑不改事实，旧修订号写入拒绝，直接修改 facts 拒绝
- 跨账号以及同一已登录账号当前范围缩小时，列表不泄露报告，详情 / 编辑 / 回收 / 恢复 / 两种导出都拒绝
- 真实运行中的复盘在第一项查询期间缩小权限：终态为 failed / SCOPE_CHANGED，仅执行一次 QuerySpec，不发布 result/review 证据；不是先完成旧范围分析再只隐藏页面
- 仅让本轮创建的源结果到期：源结果返回 410，新建保存拒绝；已保存报告保持可读
- 实际停止并重启本轮自己的 API 进程，再重新登录；PostgreSQL 报告事实、修订号和 HTML 导出字节保持一致
- 回收站、旧修订号恢复拒绝、恢复后的事实保持一致
- Markdown / HTML 中的脚本标签、图片事件与 JavaScript 链接作为转义文本；HTML 附带限制性 CSP 和无外部资源的静态 SVG
- 保存后的查看、编辑、权限检查、导出、源结果到期、回收 / 恢复与重启后查看，没有新增 Agent 或 query_metrics 调用

## 在正常本机环境执行浏览器验收

先停止本项目已有开发服务，避免生命周期脚本同时管理同一 PostgreSQL。使用已有已验证数据与锁定依赖；不需要配置真实模型。

Linux / Bash，从项目根目录执行：

```bash
# 首次安装对应 Playwright 浏览器时才执行
(cd frontend && npx playwright install chromium)
# 同一生命周期启动 PostgreSQL、API、Vue 并执行全部 3 条 E2E
bash scripts/dev.sh --test-e2e
```

Windows PowerShell，从项目根目录执行（先完成 Windows 指南的已有工具配置）：

```powershell
# 首次安装对应 Playwright 浏览器时才执行
Push-Location frontend
npx playwright install chromium
Pop-Location
.\.venv\Scripts\python.exe scripts\dev_windows.py --test-e2e
```

这两条测试入口强制 mock、禁用 .env 加载并使用临时预算账本，不会重置现有预算。

套件包含原有的完整工作台 / 跨账号 / 移动场景、延迟重置 / 快速连续动作场景，以及新建的销售复盘 → 保存 → URL 刷新 → 批注编辑 → Markdown / HTML 下载 → 取消删除 / 回收 / 恢复 → 后退导航 → 移动宽度 → 另一账号拒绝访问场景。

详细断言见 frontend/e2e/sales-workspace.spec.ts 和 frontend/e2e/sales-reports.spec.ts。运行结果及失败截图 / trace 位于 frontend/test-results；本记录没有将待运行的断言写成已通过。
